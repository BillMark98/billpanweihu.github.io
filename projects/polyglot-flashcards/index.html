What it is

A cross-platform, offline-first spaced-repetition app for daily multilingual study. It ingests a generated daily lesson, lets you approve what is actually worth learning, turns approved notes into cards, and schedules them with FSRS — with no network connection required at any point.

Languages: Latin, Ancient Greek, Japanese, French, Spanish, German, English. Japanese cards carry pitch accent.

Targets macOS, iOS, Android and web from one Dart codebase.

The lesson contract

A separate generator produces a daily Markdown lesson ending in a machine-readable flashcards-v1 block. The app reads that block, validates it against a versioned JSON Schema, and creates draft notes — not cards.

Two decisions are doing work there.

The schema is versioned, so the generator and the app can change independently without a silent format drift that corrupts a card deck you have been reviewing for months.

And the import produces drafts requiring approval, rather than cards. A generated lesson is a proposal. Automatically committing it to a review schedule means every generation error becomes something you will be quizzed on for weeks — the cost of a bad card is not the card, it is the compounding of it.

Scheduling

FSRS, rather than the SM-2 family. FSRS fits a memory model with separate difficulty and stability parameters to your actual review history, which matters most for the case this app is built around: reviewing seven languages at once, where your retention curve for Ancient Greek morphology has nothing in common with your curve for Spanish vocabulary.

Append-only review history

review_event is append-only. Undo is a compensating event, not a deletion.

This is the sort of decision that looks like overengineering until the first time the scheduler produces something surprising. With an append-only log you can replay the exact sequence of reviews that produced a given interval. With mutable state you can only observe that the interval is wrong.

Constraints enforced mechanically

The README has a section on what the app refuses to do, and the refusals are tested rather than intended. The one I like most: a test asserts that no HTTP client appears anywhere in the dependency tree.

"Offline-first" as a stated principle decays the moment someone adds a convenient package that phones home in a transitive dependency. As a failing build, it does not decay.

Documentation

Forty-two markdown documents, including an architecture guide, the markdown contract, a testing guide, an explicit list of deferred work, and a docs/decisions/ directory recording why each hard-to-reverse choice was made.

The status is stated plainly as "Milestone 1, stage 1 of 10" — the review loop, the FSRS scheduler, four screens, dark mode and an integration suite are shipped; most of the roadmap is not.
