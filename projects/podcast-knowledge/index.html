Podcast Knowledge Base

A local-first pipeline that turns a podcast episode into a timestamped transcript and then into a source-grounded, citation-carrying notebook — with transcription running on-device.

What it does

One command takes a podcast URL and returns a notebook whose every claim cites a timestamp in the transcript it came from:

uv run podcast-kb notebook "<url>" --latest

The pipeline:

Apple Podcasts / RSS URL
  → Apple Lookup API → RSS feed → episode resolution
  → atomic audio download → MLX Whisper
  → raw JSON + plain text + timestamped Markdown
  → deterministic sectioning → LLM extraction + synthesis
  → cited notebook.md

Output is plain files on your disk, intended to drop straight into Obsidian or any Markdown tool.

Transcription runs on your machine

Transcription uses MLX Whisper on Apple Silicon. No per-minute API cost, no account, and no audio leaving the machine.

That last part is the reason. Sending hours of audio to a hosted transcription service is a cost decision, but it is also a disclosure decision, and the two get conflated because the API is convenient. Running on-device removes the question.

The parts I would defend

Every stage is idempotent. Re-running the pipeline costs only the parts that are missing. This sounds like an optimisation and is actually a correctness property: it means a failure halfway through a two-hour episode is recoverable rather than restart-from-scratch, which in turn means you find out about failures instead of avoiding the code path that produces them.

Downloads are atomic. Audio is streamed to a temporary path and renamed into place only on success. A partial file that looks complete is worse than no file, because the next stage will happily transcribe it and produce plausible, truncated output.

Sectioning is deterministic, before any model sees the text. The transcript is divided by rule, not by asking a model where the topics change. The model works within a structure it did not choose, which makes its output comparable across runs and across models.

The provider layer is a gateway, not an import. Anthropic, OpenAI, MiniMax and a local MLX model sit behind one interface, with per-stage routing and escalation — cheap model for extraction, stronger model for synthesis. Swapping providers is configuration.

Grounding is the point of the knowledge layer. The notebook is built from schemas with validation and a deterministic renderer, so a claim without a source has somewhere to fail rather than somewhere to hide.

Engineering shape

Roughly 27k lines across 114 Python modules, against 39 test files and about 11.8k lines of tests — the ratio is deliberate for a pipeline where most failure modes are silent and data-dependent.

Fifty markdown documents in docs/, including a milestone board that marks the MVP complete end to end (M1–M5, K1–K4, C1) and names what is still planned: topic lenses, grounding checks, cross-episode search.

Scope

It processes publicly accessible episodes through their public RSS feeds, on the user's own machine, for personal study notes. A YouTube extension exists as a design document only and is not implemented.
